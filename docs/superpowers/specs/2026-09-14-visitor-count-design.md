# 网站访问统计设计

## 目标

在“十六”个人网站页脚公开显示两项全站统计：

- 累计访客数
- 页面访问次数

统计功能不能影响文章阅读、页面导航或 GitHub Pages 的静态部署。

## 方案

使用不蒜子提供的轻量统计脚本和计数元素。网站保持静态，不增加服务端接口、数据库或构建时密钥。

页脚显示：

```text
本站访问量：xxx 次 · 累计访客：xxx 人
```

统计脚本在全局布局中只加载一次，两个计数元素使用不蒜子约定的
`site_pv` 和 `site_uv` 标识，由服务端异步填充数值。

## 页面结构

修改 `src/layouts/BaseLayout.astro`：

1. 在页脚新增访问统计行。
2. 为访问次数和访客数分别提供稳定的 `id` 和 class。
3. 在页面底部加载统计脚本，避免阻塞 head 中的元数据和首屏渲染。

修改 `src/styles/global.css`：

1. 统计行沿用页脚的灰墨色、字号和间距。
2. 使用响应式布局，窄屏时允许统计内容自然换行。
3. 不新增醒目的卡片、徽章或装饰性背景。

## 数据流

1. 浏览器打开任意网站页面。
2. 全局布局加载统计脚本。
3. 脚本向统计服务提交当前站点和页面访问信息。
4. 统计服务异步返回全站 PV 和 UV。
5. 脚本将数值写入页脚对应元素。

## 降级与隐私

- 统计服务不可用、超时或被浏览器拦截时，网站正文仍正常显示。
- 数值未返回前显示 `统计加载中`，不在构建阶段写入伪造数据。
- 不在网站代码中保存用户身份信息、访问日志或第三方密钥。
- 不使用 CSDN、远程文章内容或远程图片资源。

## 测试

新增布局测试，验证：

- 全局布局包含不蒜子统计脚本。
- 页脚包含 `site_pv` 和 `site_uv` 两个计数节点。
- 统计脚本使用异步加载属性。

完成后运行：

```powershell
npm test
npm run build
```

生产构建必须继续通过 Astro 检查和内容门禁，且不改变文章页面数量。
